https://data.go.th/dataset/rtddi

##  กรอบการวิเคราะห์ข้อมูล (Analytical Framework)

###  1. การวิเคราะห์มิติเวลาและพฤติกรรม (Temporal & Behavioral Patterns)

####  **ช่วงเวลาอันตราย (The Deadly Hours)**
* **วัตถุประสงค์:** ค้นหาช่วงวันและเวลาที่มีอัตราการเสียชีวิตสูงที่สุด
* **รูปแบบการนำเสนอ:** `Heatmap Matrix` (วันในสัปดาห์ x ช่วงเวลาเกิดเหตุ)
* **ตัวแปรที่ใช้:** `DeadDate` (สกัดวันในสัปดาห์), `TimeRec`, `id`

####  **ฤดูกาลและเทศกาล (Seasonal & Festival Spikes)**
* **วัตถุประสงค์:** เปรียบเทียบสถิติมองหาความผันผวนช่วง 7 วันอันตราย (ปีใหม่/สงกรานต์) เทียบกับช่วงวันปกติ
* **รูปแบบการนำเสนอ:** `Multi-Line Trend Chart` พร้อมแถบไฮไลต์ช่วงเทศกาล
* **ตัวแปรที่ใช้:** `DeadDate`, `DEAD_YEAR`, `id`

####  **กลุ่มอายุและเพศเสี่ยงสูง (Demographics Risk Profile)**
* **วัตถุประสงค์:** เจาะลึกโครงสร้างประชากรที่เป็นกลุ่มเสี่ยงหลักของประเทศ
* **รูปแบบการนำเสนอ:** `Population Pyramid` / `Butterfly Chart`
* **ตัวแปรที่ใช้:** `Age` (แบ่งกลุ่มช่วงอายุ), `Sex`, `id`

---

###  2. การวิเคราะห์พาหนะและบริบทการชน (Vehicle & Crash Dynamics)

####  **รูปแบบการชนและพาหนะเสี่ยง (Crash Type & Vehicle Analysis)**
* **วัตถุประสงค์:** วิเคราะห์สัดส่วนประเภทพาหนะของผู้เสียชีวิต และรูปแบบการชนที่สร้างความสูญเสียรุนแรงที่สุด
* **รูปแบบการนำเสนอ:** `Sankey Diagram` / `Grouped Bar Chart`
* **ตัวแปรที่ใช้:** `ICD-10` (รหัสกลุ่มอุบัติเหตุ), `Vehicle`, `id`

####  **ปัจจัยเสี่ยงด้านอุปกรณ์ความปลอดภัย (Safety Equipment Risk)**
* **วัตถุประสงค์:** ประเมินความสัมพันธ์ระหว่างการไม่ใช้อุปกรณ์นิรภัยกับการเสียชีวิต
* **รูปแบบการนำเสนอ:** `Donut Chart` / `KPI Gauge`
* **ตัวแปรที่ใช้:** `RiskHelmet`, `RiskSafetyBelt`, `Vehicle`, `id`

## เว็บ Dashboard

Dashboard สร้างด้วย HTML, CSS และ JavaScript แบบไม่ต้องติดตั้ง npm packages เพิ่ม แผนที่ใช้ Leaflet และ MarkerCluster ผ่าน CDN พร้อมแผนที่พื้นหลัง OpenStreetMap ดังนั้นต้องเชื่อมต่ออินเทอร์เน็ตเพื่อโหลดแผนที่และไลบรารีส่วนนี้

1. สร้างข้อมูล join และไฟล์ที่ Dashboard ใช้ รวมสรุปเหตุการณ์ TRAMS:

   ```powershell
   .\build_dashboard_data.ps1
   ```

2. เปิดเว็บเซิร์ฟเวอร์เฉพาะในเครื่อง:

   ```powershell
   .\run_dashboard.ps1
   ```

3. เปิด `http://127.0.0.1:8000`

ตัวเตรียมข้อมูลสร้าง `data/road_fatalities_dashboard_joined.csv` สำหรับวิเคราะห์ต่อ และ `data/dashboard_data.json` สำหรับหน้าเว็บ โดย join พิกัดกับแนวเส้นถนน DOH จาก `data/ข้อมูลทะเบียนบัญชีสายทาง (Road_Cl_Line_2568).gpkg` ด้วยระยะใกล้สุดไม่เกิน 100 เมตร แล้วเชื่อมปริมาณจราจรเมื่อรหัสทางหลวงตรงกัน ตัวแผนที่ใช้เส้นถนนที่ย่อรายละเอียดเพื่อการแสดงผล แต่การจับคู่ใช้ geometry เต็ม

หน้าเว็บมีตัวกรองปีข้อมูลร่วม, ตารางเปรียบเทียบยอด RTDDI/TRAMS รายปีในมุมมองเดียว, สลับธีม, ส่งออก CSV ผู้เสียชีวิต, ดาวน์โหลด CSV เหตุการณ์ TRAMS, แผนที่ Leaflet พร้อม marker clustering และ popup, สีเส้นตามจำนวนพิกัดผู้เสียชีวิตที่จับคู่ได้ และจัดอันดับช่วงทางตามตัวกรอง ส่วน TRAMS แสดงจำนวนเหตุการณ์รายเดือน/ช่วงเวลา จังหวัด มูลเหตุสันนิษฐาน ลักษณะการเกิดเหตุ พาหนะ และระดับความรุนแรง ตารางรายปีเป็นการเทียบตัวชี้วัดตามปี ไม่ใช่การจับคู่รายเหตุหรือยอดที่นำมาบวกกัน เพราะ RTDDI เป็นระดับบุคคลผู้เสียชีวิต ส่วน TRAMS เป็นระดับเหตุการณ์

ไฟล์ `data/accidents_2023_2025.csv` เป็นข้อมูล TRAMS ต้นทางที่รวมสามปี ส่วน `data/accident_summary.json` เป็นข้อมูลสรุปขนาดเล็กที่หน้าเว็บใช้สร้างกราฟ สคริปต์ `data/build_accident_summary.py` สร้างไฟล์สรุปนี้ และถูกเรียกจาก `build_dashboard_data.ps1` หลังเตรียมข้อมูลผู้เสียชีวิตเสร็จ

สีเส้นบนแผนที่ผู้เสียชีวิตแสดงจำนวนระเบียนที่จับคู่ได้ ไม่ใช่จำนวนอุบัติเหตุทั้งหมดหรืออัตราความเสี่ยง ถนนใน GeoPackage นี้เป็นโครงข่าย DOH เท่านั้น จึงไม่มีถนนท้องถิ่นให้แสดง

### ข้อจำกัดของข้อมูล

ในไฟล์ผู้เสียชีวิต RTDDI ปัจจุบัน `Date Rec` และ `Time Rec` ว่างครบ 51,053 รายการ จึงวิเคราะห์เวลาเกิดเหตุจากระเบียนผู้เสียชีวิตไม่ได้ อย่างไรก็ตาม TRAMS มีวันและเวลาเกิดเหตุในอีกฐานข้อมูลหนึ่งและแสดงแยกไว้ในส่วนอุบัติเหตุ Dashboard จับคู่ปฏิทินวันหยุดกับ `Dead_Date` โดยตรง ผลจึงหมายถึงวันเสียชีวิตตรงกับวันในปฏิทิน ไม่ใช่ข้อยืนยันว่าอุบัติเหตุเกิดในวันนั้น ปฏิทินมีวันหยุดรายวัน แต่ไม่ได้ระบุช่วง 7 วันอันตรายครบทุกปี จึงไม่อนุมานช่วงดังกล่าวขึ้นเอง ข้อมูลหมวกนิรภัยและเข็มขัดนิรภัยใน RTDDI ว่างทั้งหมด จึงแสดงเป็นข้อมูลที่ไม่มี ไม่ใช่การไม่ใช้อุปกรณ์

จังหวัดในไฟล์ที่ใช้ได้เป็นจังหวัดตามทะเบียน/มรณบัตร (`Dead_Province`) ไม่ใช่จังหวัดเกิดเหตุ และไม่มี `Acc_Prov` ในไฟล์ที่เตรียมไว้ จึงไม่เปิดตัวกรองจังหวัดบนแผนที่เพื่อป้องกันการตีความผิด กลุ่มอายุแสดงเป็น 0–14, 15–19, 20–24, …, 60–64 และ 65+ ตามค่าที่มี

การจับคู่แนวถนนใช้พิกัดที่ผ่านการตรวจแก้ 15,229 จุด และค่าคลาดเคลื่อน 100 เมตร ตัวเลขจำนวนผู้เสียชีวิตบนถนนเป็นจำนวนดิบ ไม่ใช่อัตราความเสี่ยงต่อปริมาณจราจร

### เผยแพร่ด้วย GitHub Pages

เว็บไซต์เป็นไฟล์ static และโหลด `data/dashboard_data.json` ด้วย path แบบ relative จึงใช้กับ project site ของ GitHub Pages ได้ ขั้นตอนโดยย่อ:

1. สร้าง repository บน GitHub และเพิ่มไฟล์เว็บ (`index.html`, `app.js`, `styles.css`) พร้อม `data/dashboard_data.json` และไฟล์ที่จำเป็นสำหรับเปิดเว็บเท่านั้น
2. อย่าใส่ GeoPackage 61 MB หรือ CSV ต้นทาง/CSV joined หากไม่ต้องการเผยแพร่ไฟล์เหล่านั้น เพราะหน้าเว็บใช้ JSON ที่เตรียมไว้แล้ว
3. ตรวจทานเนื้อหาใน JSON ก่อน push: การเปิด repository เป็นสาธารณะทำให้พิกัดและข้อมูลระเบียนใน JSON ถูกเผยแพร่ตามนั้น ให้เผยแพร่เฉพาะเมื่อมีสิทธิ์และเหมาะสมกับวัตถุประสงค์
4. ใน GitHub ไปที่ **Settings → Pages → Build and deployment** เลือก **Deploy from a branch**, เลือก branch `main` และโฟลเดอร์ `/ (root)` แล้วกด **Save**
5. รอให้ workflow Pages เสร็จ แล้วเปิด URL ที่ GitHub แสดง (รูปแบบ `https://<username>.github.io/<repository>/`)

ข้อมูล JSON ปัจจุบันมีขนาดประมาณ 41 MB จึงใช้เวลาโหลดบนเครือข่ายช้าได้ ควรพิจารณาลดรูปทรงเส้น/แบ่งไฟล์หรือเตรียมข้อมูลแบบย่อก่อนเผยแพร่จริง
