# Road Accident & Fatality Dashboard (TRAMS)

## ไฟล์ BI หลังคลีนและรายละเอียดที่เกิดเหตุ

`data/clean_accidents.py` คลีน `dataset/accidents_2023_2025.csv` โดยไม่แก้ต้นฉบับ และส่งออก `dataset/accidents_cleaned.csv` แบบ UTF-8 with BOM (Excel/Power BI) ใช้ `drop_duplicates` ทั้งแถวก่อน จากนั้นเลือกหนึ่งแถวต่อ ACC_CODE ตามจำนวนช่องต้นทางที่มีข้อมูลจริงมากที่สุด ไม่นับ ACC_CODE/_id/source_file; กรณีคะแนนเท่ากันเก็บแถวที่มาก่อน ตรวจได้จาก `source_row` และ `completeness_score`

รวมคำมูลเหตุ/บริเวณ/ลักษณะเหตุ/สภาพอากาศตามกฎที่กำหนด แก้ชื่ออยุธยา สลับ Lat/Long ตามเงื่อนไข ตรวจกรอบ 5–21 / 97–106 แปลงวันที่เป็น ISO และปรับวันที่รายงานที่ก่อนเกิดเหตุ ค่าว่างข้อความใช้ ไม่ระบุ (มูลเหตุใช้ ไม่ทราบสาเหตุ) ส่วนตัวเลข พิกัด และวันเวลาที่ผิดหรือหายยังเป็น null ไม่เติมเป็น 0 เก็บฟิลด์ `original_*` กับธงการแก้ไขไว้สำหรับตรวจสอบ

ไฟล์ BI เก็บครบ 69,806 เหตุการณ์หลังลบซ้ำ แม้บางรายการไม่มีพิกัด ส่วน dashboard ผ่านขั้นตอน Polygon เพิ่มจึงมี 69,302 เหตุการณ์ ดูยอดคลีนใน `data/cleaning_summary.md` / `.json`, Mapping ที่เกิดขึ้นจริงใน `data/cleaning_mapping.csv` และประวัติทุกช่องที่แก้ใน `data/cleaning_changes.csv` (CSV ภาษาไทยทั้งหมดมี BOM)

รัน `.\build_dashboard_data.ps1` เพื่อคลีน ส่งออก BI และสร้าง dashboard ครบทั้งกระบวนการ หรือรัน `python data/clean_accidents.py` เพื่อส่งออกเฉพาะไฟล์ BI/รายงาน หน้า dashboard เพิ่มกราฟบริเวณที่เกิดเหตุที่กรองร่วมได้ ตารางรายละเอียดเหตุการณ์แบ่งหน้าละ 50 และ Popup ที่มีบริเวณ กม. และวันเวลารายงาน

## Overview และตัวกรองเวลา

`overview-analytics.js` แยก Component กราฟแนวโน้มและตาราง TRAMS จาก `app.js` กราฟอยู่ใน 01 / OVERVIEW และตารางรายปีอยู่ถัดลงมาทันที กราฟเริ่มต้นแสดง 36 เดือน พ.ศ. 2566–2568 และเลือกความละเอียดรายเดือน/รายไตรมาส/รายปีได้ โดยเปรียบเทียบอุบัติเหตุกับผู้เสียชีวิตด้วยแกนซ้าย/ขวาที่ติดป้ายแยกกัน

ตัวกรองปี/ไตรมาส/เดือนบนแถบหลักและในกราฟใช้ Global State เดียวกัน การเลือกเดือนจะเลือกไตรมาสที่ตรงกัน การเปลี่ยนไตรมาสจะล้างเดือนที่ไม่อยู่ในไตรมาสนั้น คลิกจุดกราฟเพื่อส่งช่วงเวลาไปกรอง KPI, กราฟอื่น, แผนที่, ตารางจัดอันดับ และ CSV พร้อมกัน ปุ่ม “ล้างช่วงเวลา” ล้างเฉพาะเวลา; ปุ่ม “ล้างตัวกรอง” ล้างทุกตัวกรอง ตารางรายปียังคงรวมแยกปีแต่ใช้เฉพาะไตรมาส/เดือนและตัวกรองอื่นที่เลือกอยู่

## ชั้นแผนที่ถนน DOH + DRR

แผนที่โหลดทุกเส้นจาก `data/roads.json` (DOH 3,083 ช่วง) และ `data/rural_roads.json` (DRR 3,700 ช่วง รวม 3,622 รหัสสายทาง ครอบคลุม 77 จังหวัด) จากบริการสาธารณะ [DRR FeatureServer layer 2](https://gis.drr.go.th/arcgis/rest/services/DRR_Feature/FeatureServer/2) ผลดาวน์โหลดตรวจครบตามรายการ OBJECTID ที่บริการส่งคืน ไม่ได้จำกัดเฉพาะถนนที่มีอุบัติเหตุ และไม่ใช่การยืนยันความครบถ้วนของถนนทุกสายในประเทศไทย

แยกสี: ทางหลวง 1 หลัก `#9333ea`, 2 หลัก `#1e40af`, 3 หลัก `#db2777`, 4 หลัก/อื่น ๆ `#6b7280`, ทางหลวงชนบท `#2391FF` กรองพื้นที่ตาม Geometry ที่ตัดกับ Polygon จังหวัดทุกจังหวัดที่ถนนพาดผ่าน (`data/road_areas.json`) แทนการใช้เพียงจังหวัดของจุดกึ่งกลาง เส้นเต็มไม่ได้ถูกตัดที่เขตจังหวัด

อัปเดตชั้นแสดงผลด้วย Python ตัวเดียวกับ build ซึ่งติดตั้ง dependencies GIS แล้ว:

```powershell
python data/prepare_road_overlays.py
```

สคริปต์ดาวน์โหลดตาม OBJECTID แบบแบ่งชุด ตรวจรายการตกหล่น และเก็บต้นทาง `dataset/drr_roads_source.json` กับรายงาน `data/road_overlay_meta.json` ไว้ตรวจสอบ Browser อ่านไฟล์ในเครื่อง จึงไม่ต้องเรียก DRR ทุกครั้งที่เปิดแผนที่ เมื่อ build dashboard ใหม่จะนำ Geometry ต้นฉบับ DRR สถานะ A มาร่วมเติมข้อมูลถนนในระยะ 100 เมตรด้วย

## Pipeline พิกัดและการเติมข้อมูล GIS

ข้อมูล dashboard ผ่านกรอบประเทศไทย (ละติจูด 5.61–20.46, ลองจิจูด 97.34–105.64) แล้วตรวจ `intersects` กับ Polygon จังหวัดจริง รวมจุดบนเส้นเขตด้วย เหตุการณ์ที่ไม่มีพิกัด พิกัดผิด หรืออยู่นอกขอบเขตถูกแยกเป็น `data/spatial_excluded.json`; CSV ต้นฉบับไม่ถูกแก้ ตัวเลข KPI และสรุปรายปีจึงเป็นเฉพาะเหตุการณ์ที่ผ่านขั้นตอนนี้

จาก 69,806 ACC_CODE ไม่ซ้ำ ผ่าน 69,302 เหตุการณ์ (ผู้เสียชีวิต 8,558 ราย); แยกออก 504 เหตุการณ์: พิกัดหาย/ผิด 494 และนอก Polygon 10 รายการ พิกัดนอกกรอบ 5–21 / 97–106 ถูกปรับเป็น null ในขั้นคลีนก่อนหน้านี้แล้ว สรุปขั้นตอนและยอดตรวจสอบอยู่ใน `data/spatial_quality.json`

เติมจังหวัดเฉพาะช่องว่างจาก Point-in-Polygon และติดธง `province_coordinate_conflict` เมื่อชื่อจังหวัดเดิมขัดกับพิกัด โดยไม่เขียนทับค่าต้นทาง จับคู่ถนนจาก Geometry ต้นฉบับ DOH และ DRR สถานะ A ที่ยังไม่ลดรายละเอียด ใน UTM EPSG:32647/32648 และใช้ระยะสูงสุด 100 เมตร เติมรหัส/ชื่อถนนเฉพาะช่องว่างเมื่อไม่ขัดกับรหัสเดิม และไม่เลือกอัตโนมัติหากหลายช่วงทางอยู่ใกล้เท่ากันภายใน 1 เซนติเมตร ผลล่าสุดจับคู่ DOH 64,919 และ DRR 2,599 เหตุการณ์ รวม 67,518 เหตุการณ์ ตรวจแหล่งที่มาจาก `matched_road_source`

`road_status`/`road_feature_id` เป็นผลจับคู่ใหม่; ID จากชุด joined เก่าเก็บใน `legacy_road_feature_id` ตรวจที่มาค่าที่เติมได้จาก `province_source`, `highway_ref_source`, `road_name_source` และค่า `*_original` ใน JSON/CSV ส่งออก จุดที่ไม่พบเส้นภายในระยะใช้สถานะ `no_highway_within_tolerance` ซึ่งไม่ยืนยันว่าอยู่นอกเขตทางหลวง เพราะชั้น Geometry ไม่ครอบคลุมถนนทุกประเภท

ติดตั้งเครื่องมือ GIS ในโฟลเดอร์โปรเจกต์ด้วย Python ตัวเดียวกับสคริปต์ build:

```powershell
python -m pip install --target .spatial_deps -r data/requirements-spatial.txt
.\build_dashboard_data.ps1
```

ต้องใช้ Shapely 2 และ pyproj; ระหว่าง build อ่านแพ็กเกจจาก `.spatial_deps` ได้ด้วย โฟลเดอร์นี้ไม่ถูกเก็บใน Git

แดชบอร์ดเชิงพรรณนาสำหรับข้อมูลอุบัติเหตุทางถนนจาก TRAMS พ.ศ. 2566–2568 แยกจำนวนเหตุการณ์ออกจากจำนวนผู้เสียชีวิต และแสดงเหตุการณ์บนแผนที่จากพิกัดต้นทาง ไฟล์ CSV ที่ตรวจจริงมี 71,508 แถว 40 คอลัมน์ (ข้อกำหนดเดิมระบุ 39); จำนวนนี้บันทึกใน metadata ตอนสร้างไฟล์ข้อมูล

หน้าตาใช้พื้นครีม `#F8FAED`, สี charcoal `#181717` ในส่วนเน้น/โหมดมืด, สีแดง/ส้มสำหรับผู้เสียชีวิตและผู้บาดเจ็บ และสีม่วง/น้ำเงิน/ชมพูแยกตามจำนวนหลักทางหลวง แผนที่ใช้ [Esri World Imagery](https://doc.arcgis.com/en/data-appliance/2023/maps/world-imagery.htm) ซ้อนชั้น World Transportation สำหรับชื่อถนนและป้ายแผนที่

## เริ่มใช้งาน

1. สร้างข้อมูลที่หน้าเว็บใช้จาก CSV หลัก:

   ```powershell
   .\build_dashboard_data.ps1
   ```

2. เปิดเซิร์ฟเวอร์ในเครื่อง:

   ```powershell
   .\run_dashboard.ps1
   ```

3. เปิด `http://127.0.0.1:8000`

ต้องใช้ Python ที่มี `pandas` (สคริปต์เลือก Python ที่มากับ Codex ก่อน หากไม่มีจะค้นหา `python` ใน PATH)

## กติกานับและตรวจคุณภาพ

- ไฟล์หลักคือ `dataset/accidents_2023_2025.csv` มี 71,508 แถว และข้อมูลสร้างล่าสุดมี 69,806 ค่า `ACC_CODE` ไม่ซ้ำ
- หนึ่ง `ACC_CODE` นับเป็นหนึ่งเหตุการณ์; เหตุการณ์มีผู้เสียชีวิตเมื่อตัวเลขผู้เสียชีวิตมากกว่า 0
- พบกลุ่ม `ACC_CODE` ซ้ำ 1,641 กลุ่ม โดย 448 กลุ่มมีข้อมูลหลักขัดแย้งกัน ใช้แถวที่มีข้อมูลสมบูรณ์ที่สุดตามกติกาคลีนล่าสุด และรายงานเปรียบเทียบยอดกับกติกาเลือกความสูญเสียสูงสุดเดิมไว้ใน cleaning_summary
- หลังคลีนและกรองขอบเขตเหลือ 7,307 เหตุการณ์มีผู้เสียชีวิต และ 8,558 ผู้เสียชีวิตใน dashboard โดยกู้เหตุการณ์พิกัดสลับกลับมาได้ 1 เหตุการณ์
- รายงานข้อมูลผิดปกติและกติกานับอยู่ใน `data/dashboard_data.json` (`quality`, `meta`)
- ข้อมูลที่ไม่มีค่าไม่ถูกเติมค่าในระดับแถว; ยอดรวมรายงานเฉพาะค่าที่มี และจำนวนช่องว่างถูกรายงานไว้ใน quality metrics
- ฟิลด์บาดเจ็บรวมที่ใช้ใน KPI คำนวณจากผู้บาดเจ็บสาหัส + เล็กน้อย; ค่าในต้นทางที่ไม่ตรงกันถูกนับในตัวชี้วัดคุณภาพ
- ข้อมูลแสดงความสัมพันธ์เชิงพรรณนา ไม่ยืนยันเหตุและผล

## ตัวกรองและการวิเคราะห์

- ปี พ.ศ., ไตรมาส, เดือน, ภาค, จังหวัด, ประเภทยานพาหนะ, สถานะมีผู้เสียชีวิต และค้นหารหัส/ชื่อสายทาง (ไม่มีตัวกรองหน่วยงาน)
- ตัวกรองส่วนพื้นที่และหมวดพฤติกรรม/สิ่งแวดล้อมส่งผลร่วมถึง KPI, กราฟ, ตาราง, แผนที่ และ CSV ส่งออก
- Heatmap วันในสัปดาห์ × ชั่วโมงเต็ม 24 ชั่วโมง พร้อมยอดรวมรายวันและรายชั่วโมง (ช่องรวมไม่ลงสี)
- Line chart ใน Overview เปรียบเทียบเหตุการณ์ไม่ซ้ำและผู้เสียชีวิตรายเดือน/ไตรมาส/ปี โดยใช้แกนคนละด้าน พร้อมตัวกรองเวลาที่ใช้ร่วมกับทั้ง dashboard
- Scatter plot นับเหตุการณ์แบบ DISTINCT `ACC_CODE` และรวมผู้เสียชีวิตตาม `road_feature_id`; แสดงสีแยกภูมิภาคและเลือกจุดเพื่อไฮไลต์ Geometry บนแผนที่
- กราฟสัดส่วนพาหนะ, Donut หน่วยงาน/ประเภทโครงข่ายตามฟิลด์ต้นทาง, Treemap มูลเหตุและลักษณะเหตุ, และไอคอนสภาพอากาศ
- คลิกหมวดในกราฟเพื่อกรองกราฟกลุ่มพาหนะ/มูลเหตุ/ลักษณะเหตุ/สภาพอากาศร่วมกัน; คลิกจังหวัดในแผนที่เพื่อกรอง dashboard ทุกส่วน
- แผนที่จังหวัดใช้สี choropleth ตามจำนวนเหตุการณ์ภายใต้ตัวกรองปัจจุบัน และซูมอัตโนมัติตามประเทศ/ภาค/จังหวัด
- ส่งออกเหตุการณ์ที่กรองแล้วเป็น CSV

การจัดกลุ่มคำเป็นการ normalize ค่าที่มีคำสำคัญตรงกับกติกาในหน้าเว็บ โดยเก็บหมวดที่ไม่ตรงไว้ตามข้อความต้นทาง หมวด “ประเภทโครงข่ายถนน” ใช้ฟิลด์หน่วยงาน/ผู้รับผิดชอบทางจาก TRAMS เป็นตัวแทน เนื่องจากข้อมูลนี้ไม่มีฟิลด์ประเภทโครงข่ายที่แยกชัดเจน จึงควรตีความตามข้อจำกัดดังกล่าว

## ข้อจำกัดการเชื่อมโยงข้อมูล

- แผนที่แสดงจุดเกิดเหตุจากพิกัด TRAMS; จุดสีแดงคือเหตุการณ์มีผู้เสียชีวิต และสีฟ้าคือเหตุการณ์อื่น
- เส้นถนนจริง 3,083 feature มาจาก GeoPackage กรมทางหลวง พ.ศ. 2568 และขอบเขต 77 จังหวัด/6 ภาคมาจาก [บริการ GIS ของกรมป้องกันและบรรเทาสาธารณภัย](https://gis-portal.disaster.go.th/arcgis/rest/services/MapDX/DPM_TH_Boundary/FeatureServer/1)
- เส้นถนนที่ส่งให้ browser ลดรายละเอียดเพื่อแสดงผล (tolerance ประมาณ 3 เมตร); ไฟล์ GeoPackage ต้นฉบับไม่ถูกแก้
- ตัวกรองถนนระดับจังหวัด/ภาคตรวจทุกพื้นที่ที่แนวเส้นตัดกับ Polygon ผ่าน `road_areas.json` และรายการพื้นที่ในชั้น DRR; เส้นที่พาดผ่านหลายจังหวัดแสดงได้ในทุกจังหวัดที่ผ่าน โดยยังแสดง Geometry เต็มสาย
- `dataset/accidents_dashboard_joined.csv` เก็บผลเชื่อมโยงเดิม แต่ผล `road_status`/`road_feature_id` ใน dashboard คำนวณใหม่ด้วย pipeline GIS ข้างต้น กราฟที่ใช้ผลจับคู่จะแสดงเฉพาะเหตุการณ์ที่ผ่านเกณฑ์ 100 เมตรและตรวจรหัสตรงกัน จึงยังเป็น subset ไม่ใช่อัตราความเสี่ยง และไม่มี AADT ที่เชื่อมโยงแล้ว
- รหัสทางใน GeoPackage บางรายการเติมศูนย์นำหน้า เช่น `0001`; คงรหัสต้นฉบับไว้ แต่ใช้จำนวนหลักหลังตัดศูนย์เติมหน้าสำหรับการจำแนกสี
- ขอบเขตภาคใช้ REGION_6 จากบริการ DDPM; ชื่อจังหวัด “อยุธยา” ถูกปรับเป็น “พระนครศรีอยุธยา” ให้ตรงกับขอบเขต
- ปี 2025/พ.ศ. 2568 อาจยังไม่ครบปีและอาจมีความครอบคลุมต่างจากปีอื่น ควรระวังการเทียบยอดดิบ

## ไฟล์สำคัญ

- `data/build_dashboard_data.py` สร้าง JSON จากข้อมูลต้นทางและตรวจคุณภาพ
- `data/dashboard_data.json` เหตุการณ์ระดับ `ACC_CODE` สำหรับแผนที่และตัวกรอง
- `data/accident_summary.json` สรุปสถิติรายปีสำหรับกราฟ
- `data/roads.json` แนวเส้นทางจริงและข้อมูลรหัสทางที่แปลงจาก GeoPackage
- `data/provinces.geojson` ขอบเขตจังหวัดและคุณลักษณะภูมิภาค
- `dataset/` เก็บไฟล์ต้นทางและข้อมูลอ้างอิง
